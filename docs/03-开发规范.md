# 开发规范（协作方式）

> 本文档约定我们两个人（用户 + AI 助手）在这个项目上的协作方式。

## 1. 文档驱动开发流程

每个功能遵循以下闭环：

1. **设计**：先在 docs/ 写设计（要做什么、为什么、数据流、接口），讲给用户听；
2. **确认**：用户认可后再写代码（涉及技术选型时，助手给推荐 + 理由，用户拍板）；
3. **实现**：小步实现，一次一个任务，不一次性堆大改动；
4. **验证**：编译 + 测试 + 手动演示，全部通过才算完成；
5. **提交**：按提交规范提交，并更新 docs/ 中的进度记录。

## 2. 小步迭代

- 一次只做一件事，每完成一小步就有一个"可演示"的中间结果；
- 每周结束都有能 demo 的版本（见 04-开发计划.md）；
- 用户运行、贴输出，确认通过后再进下一步。

## 3. 教学式讲解

- 关键代码要讲清"在做什么、为什么这么做"，不默认用户已经懂；
- 数据结构、接口设计、设计取舍都要说人话解释。

## 4. 报错与调试

- 以用户贴的真实报错原文为准，不猜原因；
- 新问题先定位根因，再谈修复方案。

## 5. 测试要求

- 新功能必配测试；LLM / Embedding / 网络请求全部 mock；
- 用项目 venv 跑测试：`.venv\Scripts\python -m pytest`；
- 后端测试全绿 + 前端 `tsc` 通过后才算完成。

## 6. 提交规范

- 中文 commit message，格式：`类型: 简短描述`；
- 类型：feat / fix / docs / test / refactor / chore；
- 示例：`feat: 图片入库管线（描述/标签/OCR/去重）`、`docs: 检索评测报告 v1`。

## 7. 环境约定

- Windows 11 + PowerShell，注意文件编码（统一 UTF-8）；
- Python 3.14（venv 在 backend/.venv）；Node 24（前端）；
- 敏感配置只放 .env（不进 git），模板放 .env.example。

## 8. 目录结构

```text
multimodal-asset-agent/
├── docs/            # 文档（唯一事实来源）
├── backend/
│   ├── app/
│   │   ├── api/         # 路由
│   │   ├── models/      # SQLAlchemy 模型
│   │   ├── schemas/     # Pydantic
│   │   ├── pipeline/    # 入库流水线 + 模态适配器
│   │   ├── llm/         # 多模态 API 客户端
│   │   ├── retrieval/   # 检索
│   │   ├── agent/       # LangGraph 素材助理
│   │   ├── domain/      # 领域画像
│   │   └── core/        # 配置/数据库/工具
│   ├── scripts/     # 评测脚本等
│   └── tests/
├── frontend/        # React + Vite + TS
├── data/            # 本地素材存储（gitignore）
└── docker-compose.yml
```

## 9. 优先级纪律

- P0 没做完之前不做 P1/P2；
- 任何体现不出"Agent + 多模态"价值的功能优先级调低；
- 遇到拿不准的需求，先在文档里写明取舍，再决定。
