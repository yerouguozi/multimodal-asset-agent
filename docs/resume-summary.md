# 简历项目描述：Multimodal Asset Agent（多模态素材 Agent）

> 适合写进“项目经历 / 个人项目”栏，可直接按需要裁剪。

## 一句话版本

自研的多模态素材管理 Agent：图片 / 视频 / 音频 / 文档统一入库后自动理解、打标、向量化，
支持跨模态语义检索、以图搜图、时间片断检索与 LangGraph 素材助理，并对每一步 Agent
执行过程做实时可观测的轨迹化展示。

## 简历要点（可粘贴）

- 技术栈：Python / FastAPI / SQLAlchemy / LangGraph / React 18 + TypeScript / Milvus /
  SiliconFlow 多模态模型（Qwen3-VL / SenseVoice / bge-m3 / bge-reranker）
- 实现四类素材统一的异步入库流水线：SHA-256 + pHash 去重、缩略图、OCR / 语音转写 /
  文档摘要、自动打标、统一向量化，失败自动重试（66 个 pytest 全量通过，LLM 全 mock）
- 自研混合检索：BM25 + bge-m3 向量 RRF 融合、bge-reranker 精排、按查询类型门控的
  图片 VL 向量路由；在 45 组真实查询 × 5 策略评测上 Recall@1 0.789 / Recall@5 0.956 /
  MRR 0.893，并证明“朴素多模态融合是负结果、门控启用后超越”这一可复现结论
- LangGraph 素材助理：LLM 结构化任务规划 → 多步工具循环 → 事实约束回答；
  SSE 实时推送 plan / tool / answer 结构化事件，前端渲染可交互执行轨迹，
  命中素材可直接点开详情；会话记忆落库并支持多会话新建 / 切换 / 历史回看
- 真实多用户：JWT 注册登录 + owner 维度隔离素材 / 检索 / 画像 / Agent 会话
  （未登录自动降级访客模式，保留本地体验）；素材详情内嵌音视频播放器，
  转写片段点击即跳转播放
- 可靠性工程：Agent 回答引用校验（#id 必须来自工具结果，防幻觉第二道防线）；
  全链路检索日志 + P95 延迟 / 高频查询指标接口
- 领域自适应：分类不写死，标签聚合 + LLM 洞察自动生成“素材库画像”，
  并将分布反哺为检索字段权重；每次模型调用计入成本日志
- 工程化：Docker Compose 一键部署、本地向量库 ↔ Milvus 可切换且结果一致、
  质控平台兼容评测协议、GitHub Actions CI；/eval 检索评测仪表盘与报告同源可视化

## 面试 2 分钟讲述结构

1. 问题：素材种类杂、命名乱，想按“内容语义”而不是文件名找人；且不想为一个领域写死
   一套分类规则。
2. 方案：四条流水线把素材全部翻译成“描述/标签/正文/向量”这几种统一信号，检索时按查询
   类型动态启用不同信号（门控），最后用 Agent 把检索变成对话与任务执行。
3. 关键取舍与教训：朴素三路融合在评测里反而拉低 Recall@1（-0.167），说明“多模态信号
   不是越多越好”，由此设计了按查询类型门控；向量后端本地 / Milvus 双实现并做一致性验证。
4. 工程闭环：66 个 mock 测试、45×5 检索评测报告、Docker 部署、前端把 Agent 轨迹与
   检索结果做成可交互可视化。
